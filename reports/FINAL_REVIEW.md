## 可以直接验收的软件行为

在项目根目录运行：

```powershell
.venv\Scripts\paperread doctor
.venv\Scripts\python scripts/check_project.py
.venv\Scripts\paperread --mock serve
```

Web 访问 `http://127.0.0.1:8765`，Ctrl+C 停止。可在演示页面录入 mock- 开头书籍、选择版本并新建记录。
所有演示读数和状态都明确标记为 Mock。内置浏览器已检查默认页面与表单；截图 `ui-mock-preview.png`。
检查用服务器已停止，没有留下阅读后台任务。

实际测试汇总见 `final-evidence.json`；当前最终测试集 **138 项**，涵盖数据库事务/输入/去重、
CLI、Gateway 故障、固定书写入、双重核验、取消、超时、部分延迟、进程重启、跨数据库写锁、
Windows DPAPI 合成凭证与 Web 表单/CSRF/Origin/Host/转义。

## 真实账号仍需本人完成的步骤

完整步骤与命令在 `docs/LIVE_TEST_PROTOCOL.md`：

1. 本机取得官方只读 Key；准备自己授权的目标书 WeReadGears JSON，用本机路径导入 DPAPI 存储。
2. 本人选定《安娜·卡列尼娜》的具体译本，保存实际纸质阅读记录。
3. 官方 baseline 与 App 单书/月度读数、同一账号和活动排除确认一致。
4. 本机 `probe --live --confirm` 并再次键入精确书籍/额度；仅 1–60 秒。
5. 服务器单书 + 月度增量和 App/自然日复核均成立后才记入这条记录，再决定是否提交余额。

本轮没有要求或读取真实 Cookie/Key，没有扫码，没有发出真实阅读请求。不能代替本人确认这些事实。
CI/pytest 禁止真实写入，默认模式不因环境中存在 Key 而自行启用网络。

## 仍有的限制

- 未集成安全扫码入口，不能启动原 WeReadGears 去自动登录；目前需本人已授权的本地上下文。
- 原官方字段口径存在文档差异。缺少可信单书 API 字段时直接 BLOCKED，尚未实现人工单书值替代缺失字段的快照模式。
- 小于请求额度的双增量保留 PARTIAL/写意图，直到可可靠消除未决尾部；不放宽阈值、强制成功或强制解锁。
- 远端没有公开幂等键；本地可防重并保守停止，不能承诺端到端 exactly-once。
- OS/pending 写锁约束当前 Windows 用户内的本项目实例；其他 Windows 用户、设备及客户端仍需本人暂停，不能由本程序远程强制互斥。
- 纸质日期不变，真实会话按当前服务器时间。不能把旧阅读日期强行写入历史日桶。
- 真实 API 的现场回包/兼容性、延迟、统计口径和账号一致性仍未实测；本项目不作为稳定自动同步服务发布。
- 声明 Python 3.11+，实际只验证 Windows / 3.12.4；多版本 CI 尚未执行。

用户统一验收时，可以先验收本地功能与代码。第 4 阶段的真实账号证据仍是整体业务目标完成的必要条件。
