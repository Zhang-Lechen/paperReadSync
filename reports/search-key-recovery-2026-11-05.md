# 搜索 Key 加载恢复（2026-11-05）

用户在第 3 步搜索时收到 READ_LOGIN_REQUIRED。

## 现场证据

- 当前 Windows 用户的 `default.api.dpapi` 文件存在、可解密；未在报告或日志输出 Key。
- 直接使用应用的 OfficialStats 查询《十八家诗钞》成功，返回官方书目 793852。
- 原 8766 进程的首页报告 Key 未连接；同一目录、同一启动命令在 8767 启动的新进程报告已保存。
  两者的当前用户、工作目录和 LocalAppData 环境一致。尚不能据此确定旧进程内部为何不同，
  不把问题虚构为 Key 被删除或用户没有提供 Key。
- 停止已核对身份的旧进程并替换为新版 8766 服务，未删除记录、授权或未决意图。
- 新服务 `/health` 返回 read_key.available=true、source=encrypted、key_file_exists=true；
  首页显示“已保存官方 Key”，搜索按钮已启用。
- 本轮仅授权文件检查和只读查询，真实写入尝试仍为 1，未决意图仍为 1，已核验仍为 0 秒。

## 改动

- 页面连接状态与 OfficialStats 共用相同的 `official_key` 解析器，真正读取加密文件，
  不再仅检查文件存在或把空白环境变量误判为已连接。
- Key 缺失或加密文件无法读取时，搜索返回首页第 1 步，保留书名并说明扫码不能替代只读 Key；
  不再只展示一页 READ_LOGIN_REQUIRED。没有 Key 时搜索按钮不可用。
- 增加仅本机可访问的 `/health` 运行诊断：版本、进程、路径和授权可读状态；不返回任何密钥值。
- 保留现有 Host、Origin、CSRF、无缓存和 DPAPI 保护。

## 验证

203 项测试通过；compileall、pip check、上游校验、Mock 演示及敏感格式扫描通过。
新增回归覆盖重开后读取同一加密 Key、损坏文件不误报已连接、缺失 Key 搜索返回授权区并保留查询，
以及页面和 health 不泄露 Key。

内置浏览器当前停在无法连接的历史错误页，工具拒绝访问该 data URL，未完成浏览器自动点击复核。
