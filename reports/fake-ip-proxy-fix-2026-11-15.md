# Fake-IP 代理兼容修复（2026-11-15）

## 根因证据

当前系统 HTTP/HTTPS 代理为本地代理。`i.weread.qq.com` 和 `weread.qq.com` 均被解析到 198.18.0.0/15 虚拟地址。
同一代理访问其他站点正常；HTTPX 和系统 curl 按微信读书域名建立隧道时均出现 TLS EOF。
通过 HTTPS DNS 获取真实 IPv4，再让同一代理连接该地址，保留原始域名 SNI 和证书校验，两站点均正常返回 HTTP 响应。
这定位到当前代理的域名解析/路由差异；不能仅凭这些结果判断代理软件内部是哪条规则导致。

## 修改

- 仅对已审计的两个微信读书域名、HTTPS 请求、HTTP/HTTPS 代理和本地 Fake-IP 解析启用适配。
- Google DoH 仅查询公共域名；不携带 Key、Cookie、书目、请求体。拒绝非公网地址，缓存遵循 TTL，最多 300 秒。
- HTTPX 连接池只改变代理 CONNECT 目标；保留原始 HTTP Host、TLS SNI 和证书验证。每个原始域名独立连接池。
- 本地 HTTP 代理下为授权浏览器提供临时、随机认证的回环 CONNECT 中转，操作结束关闭；不解密 TLS，不绕过阅读请求拦截。
- 解析发生在应用请求提交之前。解析或连接失败不直连回退，不重发应用请求。
- 显式锁定适配使用的 httpcore 1.0.9。
